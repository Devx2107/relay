# Bug: Inverted sender-relevance scoring for email

## Problem

In `lib/triage-ranking.ts`, the `scoreSenderRelevance` function incorrectly assigns a lower score to emails from senders that are in the `relevantAddresses` set compared to senders that are not in the set.

## Expected Behavior

Emails from senders present in the `relevantAddresses` set should receive a higher triage score (e.g., 10 or 15) to signify higher relevance, whereas unknown senders should receive a lower score (e.g., 5 or 0).

## Actual Behavior

```javascript
if (source === "email") {
  if (!sender) return 0;
  return relevantAddresses.size > 0 && relevantAddresses.has(normalizeEmail(sender)) ? 5 : 10;
}
```

If the sender is relevant, it returns 5. If they are not relevant, it returns 10.

## Reproduction Steps

1. Generate a triage briefing with emails from a sender that is included in the `relevantAddresses` set.
2. Generate a triage briefing with emails from an unknown sender.
3. Observe that the unknown sender's email receives a higher `senderRelevance` score.

## Context

This bug was caught during an AI agent code review. It directly inverses the 15% weight of the sender relevance signal.

## Relevant Files

- `lib/triage-ranking.ts`

## Constraints

Ensure the fix aligns with the calendar proximity scoring (which correctly assigns a higher score to relevant attendees, i.e., `TRIAGE_SIGNAL_WEIGHTS.senderRelevance` instead of 8).

## Implementation Plan

1. Edit `lib/triage-ranking.ts` and locate `scoreSenderRelevance`.
2. Swap the ternary operator values in the email branch so that a true condition yields `TRIAGE_SIGNAL_WEIGHTS.senderRelevance` (or 10/15) and a false condition yields a lower number (like 5 or 0).
